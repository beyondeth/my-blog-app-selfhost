# 실시간 연결

> 채팅/알림 등 실시간 이벤트를 안정적으로 수신하는 네트워크 정책

---

## 개요

실시간 기능은 모바일 환경의 네트워크 전환(포그라운드/백그라운드/재연결)을 고려해 연결 수명 주기를 설계한다.

---

## 요구사항

### REQ-01: 실시간 연결은 Bearer 토큰 기반으로 시작해야 한다(SHALL).

- 연결 시 accessToken을 인증 헤더 또는 핸드셰이크 토큰으로 전달해야 한다(SHALL).
- 연결 실패 시 즉시 재시도 정책으로 전환한다(SHALL).

### REQ-02: 인증 만료 시 실시간 연결은 자동 갱신 후 복구해야 한다(SHALL).

- 소켓 이벤트에서 인증 오류가 발생하면 갱신을 선행하고 재접속해야 한다(SHALL).
- 갱신 실패 시 오프라인 안내로 전환하고 사용자 조치를 유도해야 한다(SHALL).

### REQ-03: 앱 생명주기 이벤트마다 연결을 정합적으로 관리해야 한다(SHALL).

- 백그라운드 진입 시 불필요한 연결은 최소화한다(SHALL).
- 포그라운드 복귀 시 지연 없이 재연결해야 한다(SHALL).

### REQ-04: 이벤트 스트림 오염을 방지해야 한다(SHALL).

- 중복 메시지·중복 이벤트는 디듀핑 키로 제거해야 한다(SHALL).
- 네트워크 단절 구간의 큐잉 정책을 노출해 사용자 오해를 방지한다(SHALL).

---

## 시나리오

### Scenario 1: 채팅 진입 후 즉시 수신

- **GIVEN** 사용자가 채팅 화면에 진입한다.
- **WHEN** 소켓 연결이 완료된다.
- **THEN** 최근 메시지 이력이 즉시 정렬되어 표시된다.

### Scenario 2: 토큰 만료 재연결

- **GIVEN** 소켓 세션이 인증 만료로 종료됐다.
- **WHEN** 갱신 토큰이 유효하다.
- **THEN** 재인증 후 동일 채널로 자동 복귀한다.

### Scenario 3: 포그라운드 복귀

- **GIVEN** 앱이 백그라운드였다가 복귀한다.
- **WHEN** 네트워크가 복구됐다.
- **THEN** 실시간 연결이 다시 열리고, 누락 이벤트를 재동기화한다.

---

## 비기능 요구사항

### 성능

- 재연결 평균 시간은 2초 이내를 목표로 한다(SHOULD).

### 안정성

- 연결 끊김 이벤트는 사용자에게 명확히 표시하고 재시도 버튼을 제공해야 한다(SHALL).

## 제약사항

- 실시간 모드에서 배터리 소모가 높은 폴링 대기를 우선하지 않는다.

## 용어 정의

| 용어 | 정의 |
|------|------|
| reconnect backoff | 실패 후 재시도 간격을 점진 증가시키는 전략 |
| dedupe | 동일 이벤트 중복 제거 정책 |
| lifecycle | 앱 상태 전환(활성/비활성/백그라운드) |
