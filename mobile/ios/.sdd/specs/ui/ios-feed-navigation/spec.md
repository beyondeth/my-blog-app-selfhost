# iOS 피드/네비게이션

> 하단 탭 중심 내비게이션과 피드 상호작용을 가진 iOS 원본 UX

---

## 개요

웹과 동일한 콘텐츠를 보여도 UX는 네이티브 기준으로 설계한다. 탭 기반 주요 진입, 제스처 기반 액션, cursor 기반 점진 로딩, 스켈레톤/오류 상태를 기본 UX로 적용한다.

---

## 요구사항

### REQ-01: 하단 탭 4개 구조는 기본 탐색 경로여야 한다(SHALL).

- Feed, Explore, Compose, Profile 탭을 기본 노출해야 한다(SHALL).
- 탭 전환은 상태 보존 및 빠른 복귀를 지원해야 한다(SHALL).

### REQ-02: 피드는 무한 스크롤을 사용해야 한다(SHALL).

- 커서 기반 페이징으로 페이지 누락 없이 이어서 로드해야 한다(SHALL).
- 첫 페이지 로드는 스켈레톤으로 즉시 피드백한다(SHALL).

### REQ-03: 리스트 항목 UX는 스와이프/탭/롱프레스 동작을 지원해야 한다(SHALL).

- 핵심 액션(좋아요/댓글/공유)은 1터치 진입으로 동작해야 한다(SHALL).
- 부가 액션은 액션 시트로 가볍게 노출한다(SHALL).

### REQ-04: 오류 상태는 재시도 가능한 UX로 처리해야 한다(SHALL).

- 네트워크 오류 시 재시도 버튼을 노출한다(SHALL).
- 빈 상태, 일부 로드 실패, 하단 끝 상태를 구분해 표시해야 한다(SHALL).

---

## 시나리오

### Scenario 1: 피드 진입

- **GIVEN** 사용자가 앱을 열고 로그인했다.
- **WHEN** Feed 탭에 진입한다.
- **THEN** 스켈레톤이 보이고, 첫 페이지가 2초 이내에 표시된다.

### Scenario 2: 스크롤 기반 로드

- **GIVEN** 리스트 하단 근처에 도달한다.
- **WHEN** 더 조회 영역이 보이면
- **THEN** 다음 cursor를 요청해 추가 항목을 이어 붙인다.

### Scenario 3: 접근성 제어

- **GIVEN** 사용자가 동적 폰트 및 VoiceOver를 사용한다.
- **WHEN** 글/버튼 라벨을 탐색한다.
- **THEN** 모든 핵심 동작은 접근 가능한 라벨로 읽히고, 터치 영역은 최소 44x44를 만족해야 한다.

---

## 비기능 요구사항

### 성능

- 스크롤 시 드롭프레임 없이 60fps 유지가 기본 목표이다(SHOULD).
- 한 화면에서 동시 이미지 요청은 과도하지 않도록 제한한다(SHOULD).

### 사용성

- 화면 간 진입/이탈은 300ms 내 반응성이어야 한다(SHOULD).

## 제약사항

- 웹 네비게이션 패턴을 그대로 복제하지 않는다.
- 단일 화면에서 상태를 과도하게 중첩해 성능을 훼손해서는 안 된다.

## 용어 정의

| 용어 | 정의 |
|------|------|
