# 구현 계획: iOS 피드/네비게이션

> 하단 탭과 커서 기반 피드 UX 최적화

---

## 개요

웹 화면 재현을 넘어 iOS 사용자 동작 패턴에 맞춘 네비게이션·리스트 UX를 구현한다.

---

## 기술 결정

### 결정 1: Tab + NavigationStack + LazyVStack + AsyncImage 조합

- iOS 네이티브 탐색 체감이 가장 자연스럽고 구현 부담이 낮다.

**근거:** 터치 중심 UX, 가시적 로드 상태 표현, 대량 리스트 성능 균형.

**대안 검토:**
- 커스텀 탭 바: 세밀한 제어는 가능하나 접근성/안정성 비용 증가.
- 단일 스택 only: 다중 탭 전환 상태 보존이 약함.

---

## 구현 단계

### Phase 1: 탭/라우팅 구조

- 하단 4탭 레이아웃 및 각 탭 루트 구성.
- Feed 탭에 초기 스켈레톤과 새로고침 액션 추가.

**산출물:**
- [ ] 탭 라우팅 정의
- [ ] 상태 보존 전략
- [ ] 피드 접근성 라벨

### Phase 2: 피드 렌더링 및 목록 상호작용

- cursor 기반 페이지네이션 API 바인딩.
- 셀 하단 액션(좋아요/댓글/공유) 이벤트 분리.

**산출물:**
- [ ] lazy feed list
- [ ] pull-to-refresh
- [ ] 더보기/끝 표시

### Phase 3: 오류/오프라인/성능 보강

- 오류 유형별 상태 화면 추가.
- 이미지 캐시 정책 및 스크롤 성능 점검.

**산출물:**
- [ ] offline banner
- [ ] 실패 재시도 버튼
- [ ] 성능 측정 로그

## 리스크 분석

| 리스크 | 영향도 | 완화 전략 |
|--------|--------|----------|
| 과도한 리스트 렌더링 | 높음 | cell 분리, `Equatable` ViewModel 적용 |
| 탭 전환 지연 | 중간 | 상태 영속화 및 lazy loading 분리 |
| 접근성 회귀 | 중간 | 각 라벨/액션에 접근성 태그 필수 |
