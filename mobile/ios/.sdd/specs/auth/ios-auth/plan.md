# 구현 계획: iOS 인증

> 토큰 기반 인증, 키체인 저장, 갱신 플로우

---

## 개요

iOS 앱에서 인증은 기존 백엔드 웹 경로를 직접 사용하지 않고 모바일 전용 토큰 경로를 기준으로 구현한다.

---

## 기술 결정

### 결정 1: URLSession + AsyncImage + Keychain 저장 조합(SHALL)

- URLSession은 경량, 네이티브, 백그라운드 취약성 제어가 용이해 단일 HTTP 스택으로 통일한다.
- Keychain은 토큰 영구 보관 위험을 낮추고 iOS 보안 모델에 맞는다.

**근거:** 테스트 가능성, 런타임 오버헤드, 보안 요구 충족 측면에서 균형이 좋다.

**대안 검토:**
- 라이브러리 기반 네트워크(Alamofire)도 가능했으나 우선 표준 라이브러리 우선으로 단순화.
- UserDefaults 기반 저장은 보안 미흡으로 채택하지 않음.

---

## 구현 단계

### Phase 1: 인증 네트워크 및 저장소 구축

- `NetworkService`, `AuthService`, `KeychainTokenStore` 기본 인터페이스 생성.
- `/api/v1/mobile/auth/login`, `/refresh`, `/me`, `/logout` 엔드포인트 매핑.
- 인증 실패 처리 타입 생성.

**산출물:**
- [ ] 인증 클라이언트 인터페이스
- [ ] Keychain 토큰 스토어
- [ ] 실패 응답 매핑 모델

### Phase 2: 인터셉터/갱신 정책 구현

- `Async` 기반 요청 파이프라인에서 Authorization 헤더 자동 주입.
- 토큰 만료 시 1회 갱신 in-flight 로직 적용.
- `ME` API로 초기 인증 상태 판별 라우팅 처리.

**산출물:**
- [ ] 토큰 갱신 매니저
- [ ] 동시 refresh 동기화 큐
- [ ] 인증 상태 바인딩

### Phase 3: 통합 및 안정화

- 스플래시/온보딩/로그인 화면 연결.
- 갱신 실패 시 강제 로그아웃 플로우 정합.
- UX 문구/리트라이/로딩 상태 통합.

**산출물:**
- [ ] 인증 플로우 뷰
- [ ] 재로그인 리커버리 UI
- [ ] 운영 로그 분류 가이드

| 리스크 | 영향도 | 완화 전략 |
|--------|--------|----------|
| 토큰 갱신 충돌 | 높음 | 단일 in-flight 큐와 요청 취소 정책 적용 |
| 네트워크 지연 | 중간 | 캐시된 me 체크 + 타임아웃 가드 |

## 테스트 전략

### 단위 테스트

- `TokenStore`, `TokenRefreshCoordinator`, 인증 매퍼 로직.

### 통합 테스트

- `/api/v1/mobile/auth/login`, `/refresh`의 모의 API 응답으로 성공/실패 경로 검증.

### 수동 테스트

- 앱 시작 시 자동 로그인 복구
- 다중 동시 요청 401 처리

### 성능 기준

- 갱신 시간 P95 400ms 목표
