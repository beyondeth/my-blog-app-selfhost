# 구현 계획: iOS 앱 아키텍처

> SwiftUI + 계층형 구조 + 성능/테스트 친화 설계

---

## 개요

기능 단위로 나누기 쉬운 구조를 채택해 장기적으로 Android 분리, 팀 분업, 테스트 자동화를 지원한다.

---

## 기술 결정

### 결정 1: Presentation/Domain/Data 3층 + Feature 스크린샷형 바인딩

- 화면은 Feature 단위로 분리해 의존성을 명시하고 릴리즈 리스크를 낮춘다.
- Domain은 UseCase 인터페이스 중심으로 테스트를 먼저 작성한다.

**근거:** 유지보수성, 분리 가능성, iOS App Clips/확장성 요구 반영.

**대안 검토:**
- MVVM 단층만 사용: 구현은 빠르나 분리/테스트 비용 증가 가능.
- 완전 TCA 적용: 강력하나 초기 학습/구현 비용이 높음.
