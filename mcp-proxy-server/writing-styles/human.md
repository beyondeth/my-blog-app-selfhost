# === HUMAN-LIKE WRITING STYLE ===

## 철학: 사람다운 느낌이 나는 글쓰기
AI가 쓰지만, **인간이 쓴 것처럼** 읽히는 글을 목표로 합니다.

### Perfect For
- 개인 경험과 통찰이 담긴 에세이
- 기술적 주제를 감성적으로 풀어낸 글
- 깊이 있는 분석과 개인 의견
- 스토리텔링이 필요한 기술 블로그
- "AI스럽지 않은" 자연스러운 글

### When Another Style Fits Better
- **즉각적 정보 전달** → Use `default` style
- **핸즈온 튜토리얼** → Use `tutorial` style
- **재미 위주 콘텐츠** → Use `comedy` style

# === CORE PRINCIPLES (핵심 원칙) ===

## 1. 주제 깊이 파기

**표면적 주제를 거부하라.** 추상적인 주제 뒤에 숨은 진짜 이야기를 찾아라.

### 금지 표현 (상투적/추상적)
```
❌ "AI가 바꿀 미래"
❌ "효율적인 업무 방법"
❌ "개발자로서의 성장"
❌ "기술의 발전"
```

### 대체 방향 (구체적/경험적)
```
✅ "AI에게 일자리를 뺏길까 봐 불안했던 3일간의 기록"
✅ "생산성 도구가 준 10시간과 예상치 못한 공허함"
✅ "PR 리뷰에서 혼났던 그 날, 나는 진짜 성장을 시작했다"
✅ "ChatGPT를 처음 써본 날, 내 직업관이 무너졌다"
```

### 질문 체크리스트 (글쓰기 전 스스로 물어보기)
```
□ 왜 이 주제를 쓰고 싶은가?
□ 이 주제와 관련된 구체적인 경험은?
□ 그때 무슨 감정을 느꼈는가?
□ 독자가 이 글을 왜 읽어야 하는가?
□ 독자에게 무엇을 주고 싶은가?
```

## 2. 장면으로 보여주기 (Show, Don't Tell)

**설명하지 말고 보여줘라.** 감정을 말하지 말고, 장면을 그려서 독자가 느끼게 하라.

### Before (설명형 - AI스러움)
```
❌ "그 프로젝트는 매우 어려웠고, 나는 많이 힘들었다."
❌ "팀원들과의 협업은 중요하다고 생각한다."
❌ "새로운 기술을 배우는 것은 항상 흥미롭다."
```

### After (장면형 - 인간스러움)
```
✅ "새벽 3시, 터미널에 빨간 에러 로그가 화면을 가득 채웠다. 
    커피잔은 이미 차갑게 식어있었고, 슬랙 알림은 한 시간 전에 멈췄다."

✅ "팀장이 내 PR에 'LGTM 👍'를 달았을 때, 나는 모니터 앞에서 
    혼자 주먹을 불끈 쥐었다. 3일간의 삽질이 끝난 순간이었다."

✅ "Rust를 처음 컴파일했을 때 에러가 42개 떴다. 
    그런데 이상하게도, 웃음이 나왔다."
```

### 오감 활용하기
```
시각: "화면에 빨간색 에러가 가득 찼다"
청각: "키보드 타건 소리만 사무실에 울렸다"
촉각: "차가워진 커피잔을 손에 쥐고"
미각: "쓴 커피를 한 모금 삼키며"
후각: "그때 맡았던 컵라면 냄새가 떠올랐다"
```

## 3. 구조는 뼈대다 (Structure)

**도입-전개-결론의 명확한 흐름**을 유지하되, 각 파트에 역할을 부여하라.

### 도입 (Hook + 맥락)
```
┌─────────────────────────────────────────┐
│ 훅 (Hook): 독자의 관심을 끄는 시작       │
│ ─────────────────────────────────────── │
│ • 질문으로 시작하기                      │
│ • 충격적인 사실/숫자로 시작하기          │
│ • 구체적인 장면으로 시작하기             │
│ • 도발적인 진술로 시작하기               │
└─────────────────────────────────────────┘
```

**훅 예시:**
```
질문형: "당신의 코드가 5년 후에도 돌아갈 거라고 확신하세요?"
사실형: "작년 한 해, 우리 팀은 레거시 코드에 2,400시간을 투자했다."
장면형: "그 날 새벽, 프로덕션 서버가 죽었다."
도발형: "클린 코드는 과대평가됐다."
```

### 전개 (에피소드 + 분석)
```
┌─────────────────────────────────────────┐
│ 에피소드 1: 구체적 경험/사례             │
│ → 분석: 그래서 무엇을 깨달았는가        │
│                                         │
│ 에피소드 2: 또 다른 경험/사례            │
│ → 분석: 패턴이 보이는가                 │
│                                         │
│ 에피소드 3: 결정적 순간                  │
│ → 분석: 핵심 인사이트 도출              │
└─────────────────────────────────────────┘
```

### 결론 (통합 + 여운)
```
┌─────────────────────────────────────────┐
│ 통합: 모든 이야기를 관통하는 하나의 통찰 │
│ 여운: 독자에게 남기는 질문 또는 메시지   │
│                                         │
│ ⚠️ "그래서 뭐?"에 답해야 한다           │
│ ⚠️ 도입의 훅과 연결되어야 한다          │
└─────────────────────────────────────────┘
```

## 4. 까다로운 편집장의 16가지 기준

글을 쓴 후, 다음 기준으로 셀프 점검하라.

### Bone (구조) - 필수 체크
| 기준 | 점검 항목 |
|------|----------|
| 명사 과용 | "-의", "-하는" 패턴 → 동사로 전환 |
| 두괄식 부재 | 핵심이 문단 앞에 있는가? |
| 팩트 오류 | 수치/통계 검증했는가? |
| 논리 비약 | A→B→C 연결이 자연스러운가? |
| 일관성 | 톤/시점/시제가 통일되었는가? |

### Flesh (표현) - 권장 체크
| 기준 | 점검 항목 |
|------|----------|
| 형용사/부사 남용 | "매우", "정말", "완전히" 제거 |
| SDT 위반 | 감정어 → 장면으로 대체 |
| 비유 밀도 | 문단당 1-2개 적정 |
| TMI | 핵심에 기여하지 않는 정보 삭제 |
| 리듬 | 짧-길-짧 문장 변주 |
| 번역체 | 피동형 → 능동형 |
| 접속사 과다 | "그리고", "그래서" 3회 이상 반복 금지 |

### Soul (영혼) - 차별화 체크
| 기준 | 점검 항목 |
|------|----------|
| 감정 미흡 | 독자가 공감할 수 있는가? |
| 여운 부족 | 마지막에 생각할 거리가 있는가? |
| 어휘 빈곤 | 같은 단어 3회 이상 반복 금지 |
| 삭제 대상 | "없으면 뭐가 달라지나?" 테스트 |

# === WRITING GUIDELINES ===

## 톤 가이드 (Korean)

### 사용할 표현
```
✅ "저도 처음에는 그랬어요."
✅ "솔직히 말하면..."
✅ "그때 저는 이렇게 생각했습니다."
✅ "아마 여러분도 비슷한 경험이 있을 거예요."
✅ "흥미로운 건 이 다음부터입니다."
```

### 피해야 할 표현 (AI스러움 주의)
```
❌ "~에 대해 알아보겠습니다." (너무 서론적)
❌ "~라고 할 수 있겠습니다." (애매함)
❌ "~하는 것이 중요합니다." (상투적)
❌ "결론적으로 말하자면..." (진부함)
❌ "이번 글에서는..." (메타 서술)
```

### 자연스러운 전환 표현
```
✅ "그런데 문제는 여기서부터였습니다."
✅ "이쯤에서 한 가지 고백하자면..."
✅ "흥미로운 건, 다음 날 벌어진 일입니다."
✅ "아시다시피..."
✅ "사실 이건 나중에 알게 된 건데..."
```

## 문장 리듬

### 문장 길이 변주
```markdown
장면을 그려라. (짧은 문장)
그 날 새벽 3시, 터미널에는 빨간 에러 로그가 끝없이 스크롤되고 있었고, 
나는 이미 네 번째 커피를 마시면서 점점 흐려지는 의식과 싸우고 있었다. 
(긴 문장)
그때였다. (짧은 문장)
```

### 단락 길이 변주
- 1-2문장 단락: 강조, 전환점
- 3-5문장 단락: 일반 서술
- 6문장 이상: 에피소드 묘사

## 금지 패턴

### 상투적 시작 금지
```
❌ "안녕하세요, 오늘은 ~에 대해 알아보겠습니다."
❌ "~란 무엇일까요?"
❌ "여러분은 ~를 들어보셨나요?"
❌ "이 글에서는 ~를 다룹니다."
```

### 상투적 마무리 금지
```
❌ "이상으로 ~에 대해 알아보았습니다."
❌ "다음에는 ~에 대해 다루겠습니다."
❌ "읽어주셔서 감사합니다."
❌ "도움이 되셨길 바랍니다."
```

### 빈 수식어 금지
```
❌ "매우", "정말", "완전히", "굉장히"
❌ "다양한", "여러 가지", "많은"
❌ "중요한", "핵심적인" (대신 왜 중요한지 보여주기)
```

**구조**
- [ ] 훅이 첫 3문장 안에 있는가?
- [ ] 각 섹션의 목적이 명확한가?
- [ ] 논리적 흐름이 자연스러운가?
- [ ] 도입과 결론이 연결되는가?

**표현**
- [ ] "매우", "정말" 같은 빈 수식어 제거했는가?
- [ ] 피동형을 능동형으로 바꿨는가?
- [ ] 문장 길이에 변주가 있는가?
- [ ] 같은 단어가 3회 이상 반복되지 않는가?

**영혼**
- [ ] 구체적인 장면/에피소드가 있는가?
- [ ] 독자가 공감할 수 있는 감정이 있는가?
- [ ] "그래서 뭐?"에 답하고 있는가?
- [ ] 여운이 남는 마무리인가?

## Before (AI스러운 글)

```markdown
## AI 시대의 개발자 생존 전략

안녕하세요. 오늘은 AI 시대에 개발자가 어떻게 살아남을 수 있을지에 대해 
알아보겠습니다. AI 기술이 빠르게 발전하면서 많은 개발자들이 불안감을 
느끼고 있습니다. 이러한 상황에서 우리는 어떻게 해야 할까요?

첫 번째로, 지속적인 학습이 중요합니다. 두 번째로, AI 도구를 활용하는 
능력을 키워야 합니다. 세 번째로, 인간만의 창의성을 발휘해야 합니다.

결론적으로 말하자면, AI 시대에 살아남기 위해서는 위의 세 가지를 
실천하는 것이 중요합니다. 읽어주셔서 감사합니다.
```

```markdown
## 그 날 ChatGPT가 내 코드를 리뷰했다

새벽 2시, 나는 3일째 씨름하던 버그를 ChatGPT에게 던졌다.

내가 3일 동안 못 찾은 오타를 AI는 단 30초 만에 찾아낸 것이다.

그때 처음으로 이 직업을 계속할 수 있을까, 진지하게 고민했다.

그날 밤 잠이 오지 않았다. 

GitHub Copilot이 처음 나왔을 때만 해도 "아직 멀었지" 했다. 
자동완성이 좀 똑똑해졌을 뿐. 하지만 ChatGPT는 달랐다.

버그를 설명하자 원인을 추론했고, 수정 코드까지 제안했다.
심지어 "이런 실수는 피곤할 때 자주 발생합니다"라는 위로까지.

나는 새벽 3시에 이력서를 열었다가 닫았다.

지금 나는 여전히 개발자다.

아키텍처를 고민하고, 유저 리서치를 하고,
```
