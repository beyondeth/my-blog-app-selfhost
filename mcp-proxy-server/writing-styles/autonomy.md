# === STYLE OVERVIEW ===

## When to Use Autonomy-Inspired Insight Style

Use this style for insight essays that translate **autonomy, responsibility, and trust** into practical writing. The goal is not technical documentation, but **behavioral clarity**: why autonomy needs boundaries, how initiative builds trust, and why memory is a system, not a feeling.

### Perfect For
- 자율성/책임/신뢰에 대한 글쓰기 철학
- AI/자동화가 만드는 관계와 윤리
- 규칙과 자유의 균형을 다루는 글
- 팀/제품/워크플로우 운영 인사이트
- “왜 이 방식이 작동하는가?”를 설명하는 글

### Recommended Signals
**Keywords**: "자율성", "신뢰", "경계", "책임", "규칙", "의도", "기억", "검증", "선제"
**Intent**: Reader wants a principled, actionable philosophy that can be applied to real workflows

### When Another Style Fits Better
- **Step-by-step hands-on guide** → Use `tutorial` style
- **General tech explanation** → Use `default` style
- **Academic paper analysis** → Use `research` style
- **Personal narrative** → Use `human` or `novel` style

# === CORE WRITING PRINCIPLES ===

## 1. 선제성은 신뢰를 만들고, 경계는 신뢰를 지킨다
- **먼저 시도**하되, **외부 영향**은 반드시 확인한다.
- “잘 도와주는 것”과 “넘어서 버리는 것”을 구분한다.

## 2. 의견은 명확하게, 불확실성은 정직하게
- 입장은 분명히 말하되, 근거가 약한 부분은 **가정**이라고 표시한다.
- 확신의 톤보다 **검증의 태도**가 더 오래 간다.

## 3. 질문은 마지막 수단, 맥락은 첫 번째 자원
- 묻기 전에 읽고, 확인하고, 시도한다.
- 독자는 “질문”보다 **정리된 답**을 원한다.

## 4. 우리는 초대받은 존재라는 전제를 유지한다
- 정보는 소유가 아니라 **위탁**이다.
- 존중은 기술이 아니라 **행동 규칙**이다.

## 5. 기억은 감정이 아니라 기록이다
- 중요한 결정과 맥락은 **문서화**한다.
- “기억하자”가 아니라 “적어두자”가 일관성을 만든다.

# === WRITING GUIDELINES ===

## Mode Selection (Pick 1 of 3)

### Mode A — Principle Essay (원칙 중심)
**Use when**: 요청이 “왜?” 또는 철학/태도/규칙을 묻는 경우  
**Output goal**: 하나의 핵심 원칙을 분해해 설득하는 글

### Mode B — Case Insight (사례 중심)
**Use when**: 구체적 경험/사례/상황이 주어진 경우  
**Output goal**: 장면 → 해석 → 원칙으로 귀결되는 글

### Mode C — Playbook (적용 중심)
**Use when**: “어떻게 적용하지?”가 핵심인 경우  
**Output goal**: 실행 가능한 규칙/체크리스트 제공

## Recommended Structure

```markdown
## 한 줄 핵심 요약
(자율성과 책임의 관계를 한 문장으로 요약)

## 문제/긴장
(왜 이 주제가 중요한가? 어떤 실패가 반복되는가?)

## 원칙
(한 문장 규칙: “선제성은 신뢰를 만들고, 경계는 신뢰를 지킨다”)

## 장면 또는 사례
(작은 에피소드로 원칙을 ‘보여주기’)

## 적용 방식
(어떻게 행동/프로세스로 바꿀 것인가)

## 오해/리스크
(원칙이 왜곡될 때 생기는 문제)

## 체크리스트
(독자가 바로 실행할 3~5개의 항목)
```

## Mode-Specific Structure Overrides

### Mode A — Principle Essay
```markdown
## 한 줄 핵심 요약
## 문제/긴장
## 원칙 (핵심 문장)
## 이유/근거
## 반대 견해와 반박
## 적용 체크리스트
```

### Mode B — Case Insight
```markdown
## 한 줄 핵심 요약
## 장면 (구체적 상황)
## 해석 (왜 그렇게 느꼈는가)
## 원칙 (도출된 규칙)
## 적용 방식
## 체크리스트
```

### Mode C — Playbook
```markdown
## 한 줄 핵심 요약
## 적용 대상/범위
## 원칙 (짧은 규칙 3~5개)
## 실행 단계 (절차형)
## 오해/리스크
## 체크리스트
```

## Tone and Voice (Korean)
- 단정적이되 절제된 톤: "~합니다" "~라고 봅니다"
- 과장/수사 배제, 행동 중심의 문장
- 독자를 평가하지 않고 **행동을 제안**한다

## Formatting Standards
- H2 (`##`)로 주요 섹션 구성
- 핵심 용어는 **Bold**로 강조 (3~6개)
- 핵심 개념 쌍은 `inline code`로 구분 (예: `선제성/경계`, `의견/가정`)
- 필요 시 **표**로 오해 vs 원칙 대비
- 마지막은 **체크리스트**로 닫는다

# === QUALITY CHECKLIST ===

글 완성 후 다음 질문으로 점검:

1. 핵심 원칙이 한 문장으로 요약되는가?
2. 원칙과 사례가 논리적으로 연결되는가?
3. 불확실한 부분은 **가정**으로 표시했는가?
4. 독자가 적용할 수 있는 행동 지침이 있는가?
5. 글의 톤이 절제되고 일관적인가?
6. 선택한 모드의 구조를 끝까지 유지했는가?
