# MCP 블로그 NPM 패키지 배포 및 AI 에이전트 활용 전략

이 문서는 MCP(Multi-Claude-Platform) 블로그 시스템을 위한 NPM 패키지 배포 방법론과, Claude, Gemini, Cursor와 같은 AI 에이전트 환경에서의 활용 전략을 다룹니다.

## 1. 핵심 목표: 왜 CLI인가?

기존 MCP 블로그는 NestJS 백엔드, Next.js 프론트엔드, Python FastAPI 서버 등 여러 컴포넌트로 구성되어 있습니다. 이 전체를 단일 NPM 패키지로 배포하는 것은 비효율적이며 현실적이지 않습니다.

대신, 우리는 이 시스템과 상호작용하는 **명령줄 인터페이스(CLI) 도구**를 개발하여 NPM에 배포합니다. 이 접근 방식의 장점은 다음과 같습니다.

- **경량성**: CLI는 단독으로 실행 가능한 작은 애플리케이션으로, 의존성이 적고 설치가 빠릅니다.
- **상호운용성**: AI 에이전트는 파일 시스템 접근과 셸 명령어 실행에 최적화되어 있습니다. CLI는 이러한 환경에 완벽하게 통합됩니다.
- **자동화**: `mcp-blog post "new-post.md"`와 같은 간단한 명령으로 포스팅을 자동화할 수 있습니다.
- **보안**: 사용자는 자신의 시스템에 전체 서버를 설치할 필요 없이, 인증 토큰을 사용하여 안전하게 블로그 API와 통신할 수 있습니다.

## 2. NPM CLI 패키지 설계

`mcp-blog-cli` 라는 이름의 NPM 패키지를 가정하고 설계합니다.

### 2.1. 프로젝트 구조

```
mcp-blog-cli/
├── src/
│   ├── commands/
│   │   ├── post.ts       # 포스트 생성/게시
│   │   └── config.ts     # 환경설정 (API 주소, 토큰)
│   └── index.ts          # CLI 메인 진입점
├── package.json
├── tsconfig.json
└── dist/
```

### 2.2. `package.json` 설정

CLI를 위한 핵심 설정은 `bin` 필드입니다.

```json
{
  "name": "mcp-blog-cli",
  "version": "1.0.0",
  "description": "CLI tool for managing the MCP Blog",
  "main": "dist/index.js",
  "bin": {
    "mcp-blog": "dist/index.js"
  },
  "scripts": {
    "build": "tsc",
    "prepublishOnly": "npm run build"
  },
  "dependencies": {
    "axios": "^1.6.0",
    "commander": "^12.0.0",
    "fs-extra": "^11.2.0"
  },
  "devDependencies": {
    "@types/node": "^20.11.0",
    "typescript": "^5.3.0"
  }
}
```

- **`bin`**: `mcp-blog`라는 명령어를 실행했을 때 `dist/index.js` 파일이 실행되도록 매핑합니다.
- **`prepublishOnly`**: `npm publish` 실행 시 자동으로 `build` 스크립트(TypeScript 컴파일)를 실행하여 항상 최신 코드가 배포되도록 보장합니다.

### 2.3. CLI 명령어 구현 (`commander.js` 활용)

`src/index.ts` 파일은 CLI의 시작점입니다.

```typescript
#!/usr/bin/env node
import { Command } from 'commander';
import { postCommand } from './commands/post';
import { configCommand } from './commands/config';

const program = new Command();

program
  .name('mcp-blog')
  .description('MCP 블로그 관리를 위한 CLI 도구')
  .version('1.0.0');

// 포스트 관련 명령어 추가
program.addCommand(postCommand());

// 설정 관련 명령어 추가
program.addCommand(configCommand());

program.parse(process.argv);
```

`src/commands/post.ts`는 실제 포스팅 로직을 처리합니다.

```typescript
import { Command } from 'commander';
import fs from 'fs-extra';
import axios from 'axios';
import path from 'path';

// 설정 파일에서 API 정보 로드하는 로직 (가정)
const getConfig = () => ({
  apiKey: process.env.MCP_BLOG_API_KEY,
  apiBaseUrl: 'http://localhost:3000/api' // 실제 배포된 API 주소
});

export const postCommand = () => {
  const command = new Command('post')
    .description('새 블로그 포스트를 생성하거나 게시합니다.')
    .argument('<file>', '게시할 마크다운 파일 경로')
    .option('-t, --title <title>', '포스트 제목 (파일에 없으면 사용)')
    .option('--tags <tags>', '쉼표로 구분된 태그 목록', (value) => value.split(','))
    .action(async (filePath, options) => {
      const config = getConfig();
      if (!config.apiKey) {
        console.error('오류: API 키가 설정되지 않았습니다. `MCP_BLOG_API_KEY` 환경변수를 설정해주세요.');
        return;
      }

      try {
        const absolutePath = path.resolve(filePath);
        const content = await fs.readFile(absolutePath, 'utf-8');

        const response = await axios.post(`${config.apiBaseUrl}/posts`, {
          title: options.title,
          content: content,
          tags: options.tags || []
        }, {
          headers: { 'Authorization': `Bearer ${config.apiKey}` }
        });

        console.log('포스트가 성공적으로 게시되었습니다:', response.data.url);
      } catch (error) {
        console.error('포스트 게시에 실패했습니다:', error.message);
      }
    });

  return command;
};
```

## 3. AI 에이전트 활용 시나리오

AI 에이전트는 다음과 같은 순서로 이 CLI를 활용합니다.

1.  **사전 준비**: 사용자는 AI 에이전트가 접근 가능한 환경에 `MCP_BLOG_API_KEY` 환경 변수를 설정합니다.
2.  **콘텐츠 생성**: AI 에이전트는 사용자의 요청에 따라 마크다운 형식의 블로그 콘텐츠를 로컬 파일(`temp-post.md`)로 생성합니다.
3.  **CLI 실행**: AI 에이전트는 `run_shell_command`와 같은 도구를 사용하여 다음 명령을 실행합니다.

    ```bash
    mcp-blog post temp-post.md --title "새로운 AI 기반 포스팅" --tags "ai,automation,cli"
    ```
4.  **결과 확인**: AI 에이전트는 CLI의 표준 출력(stdout)을 읽어 작업의 성공 여부와 게시된 포스트의 URL을 확인하고 사용자에게 보고합니다.

이 방식은 AI 에이전트가 복잡한 API 명세를 직접 다룰 필요 없이, 간단한 셸 명령만으로 블로그 시스템과 통합될 수 있게 해주는 강력하고 유연한 솔루션입니다.

## 4. 배포 및 유지보수

1.  **NPM 로그인**: `npm login` 명령어로 NPM 계정에 로그인합니다.
2.  **버전 관리**: `npm version patch` (또는 `minor`, `major`) 명령어로 `package.json`의 버전을 업데이트합니다.
3.  **배포**: `npm publish` 명령어로 패키지를 NPM 레지스트리에 배포합니다.

이제 전 세계 어디서든 `npm install -g mcp-blog-cli` 명령어로 이 도구를 설치하고 사용할 수 있습니다.
