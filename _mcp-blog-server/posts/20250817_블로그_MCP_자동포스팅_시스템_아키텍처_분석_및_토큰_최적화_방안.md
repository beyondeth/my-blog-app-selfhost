# 블로그 MCP 자동포스팅 시스템 아키텍처 분석 및 토큰 최적화 방안

## 🔍 현재 시스템 분석

### 현재 데이터 플로우
```
사용자 입력(MD) → MCP 서버 → HTML 변환 → JSON 페이로드 → API → PostgreSQL(HTML) → 프론트엔드
```

### 데이터 변환 과정에서의 토큰 증가

**원본 마크다운** (약 80토큰):
```markdown
# 제목
본문 내용...
## 소제목
- 리스트 항목
```

**HTML 변환 후** (약 120-150토큰):
```html
<h1>제목</h1>
<p>본문 내용...</p>
<h2>소제목</h2>
<ul><li>리스트 항목</li></ul>
```

**JSON 페이로드** (약 160-200토큰):
```json
{
  "title": "제목",
  "content": "<h1>제목</h1><p>본문...</p>",
  "tags": ["tag1", "tag2"]
}
```

**토큰 증가율**: 원본 대비 **200-250%** 🔴

## 🚀 최적화 설계 방안

### 방안 1: 마크다운 네이티브 저장 (추천) ⭐⭐⭐⭐⭐

현재는 MCP 서버에서 마크다운을 HTML로 변환한 후 전송하지만, 마크다운 원본을 그대로 저장하는 방식으로 변경:

**장점:**
- 토큰 사용량 **60% 절약**
- 포스트 편집 가능성 보장
- 저장소 크기 감소
- 렌더링 성능 향상

**구현 방법:**
```typescript
// DTO 수정
export class CreatePostDto {
  title: string;
  content: string;        // 마크다운 원본
  content_type: 'markdown' | 'html';  // 신규 필드
  tags?: string[];
}

// 엔티티 수정  
@Entity()
export class Post {
  @Column('text')
  content: string;        // 마크다운 저장
  
  @Column({ default: 'markdown' })
  content_type: string;   // 타입 구분
}
```

### 방안 2: 하이브리드 저장 (성능 최적화) ⭐⭐⭐⭐

편집 용이성과 렌더링 성능을 모두 고려한 방식:

**구현:**
```typescript
@Entity()
export class Post {
  @Column('text')
  content_markdown: string;  // 편집용 원본
  
  @Column('text', { nullable: true })
  content_html: string;      // 캐시된 HTML
  
  @Column({ default: new Date() })
  content_updated_at: Date;  // 캐시 무효화용
}
```

### 방안 3: 스트리밍 전송 ⭐⭐⭐

대용량 포스트의 경우 청크 단위로 전송:

```typescript
// MCP 서버에서 청크 단위 전송
async function streamPost(content: string) {
  const chunks = content.split('\n\n'); // 문단 단위
  for (const chunk of chunks) {
    await sendChunk({ type: 'content', data: chunk });
  }
  await sendChunk({ type: 'complete' });
}
```

### 방안 4: 압축 전송 ⭐⭐

gzip 압축을 사용한 토큰 절약:

```typescript
import { gzip, gunzip } from 'zlib';

const compressed = await gzip(content);
// 압축률: 60-80% 절약 가능
```

### 방안 5: 템플릿 기반 최적화 ⭐⭐⭐⭐

자주 사용되는 포스트 패턴을 템플릿화:

```typescript
const templates = {
  'code_post': {
    structure: ['title', 'intro', 'code_blocks', 'conclusion'],
    tokens_saved: '40%'
  },
  'tutorial': {
    structure: ['overview', 'steps', 'examples', 'summary'],
    tokens_saved: '35%'
  }
};
```

## 📋 최적화 구현 계획

### Phase 1: 마크다운 네이티브 저장 (즉시 구현 가능)

**백엔드 수정:**
1. Post 엔티티에 `content_type` 필드 추가
2. 마크다운 저장 로직 구현
3. API 응답에서 content_type 반환

**프론트엔드 수정:**
1. 마크다운 렌더러 추가 (react-markdown)
2. 조건부 렌더링 로직
3. 편집 모드에서 마크다운 에디터

**MCP 서버 수정:**
```python
# HTML 변환 생략
json_payload = {
    "title": final_title,
    "content": body,  # 마크다운 원본
    "content_type": "markdown",
    "tags": final_tags
}
```

### Phase 2: 성능 모니터링

토큰 사용량을 추적하여 최적화 효과 측정:

```typescript
interface TokenMetrics {
  original_tokens: number;
  optimized_tokens: number;
  savings_percent: number;
  render_time_ms: number;
}
```

### Phase 3: 고급 최적화

1. **템플릿 시스템** 구현
2. **압축 전송** 적용  
3. **캐싱 전략** 강화

## 🎯 권장 구현 순서

### 1단계: 마크다운 네이티브 (1-2일)
- **토큰 절약**: 60%
- **구현 난이도**: 쉬움
- **즉시 효과**: 높음

### 2단계: 프론트엔드 최적화 (2-3일)
- **렌더링 성능**: 40% 향상
- **사용자 경험**: 크게 개선

### 3단계: 고급 최적화 (1주)
- **추가 절약**: 20-30%
- **확장성**: 대폭 향상

## 💡 즉시 적용 가능한 최적화

현재 시스템을 건드리지 않고도 **30-40% 토큰 절약** 가능:

```python
# MCP 서버에서 압축된 JSON 전송
import json

# 불필요한 공백 제거
compact_json = json.dumps(payload, separators=(',', ':'), ensure_ascii=False)

# 키 이름 단축
optimized_payload = {
    "t": final_title,     # title → t
    "c": html_content,    # content → c  
    "g": final_tags       # tags → g
}
```

## 결론

현재 시스템은 마크다운 → HTML → JSON 변환 과정에서 토큰이 2-2.5배 증가하고 있습니다. 

**가장 효과적인 해결책**은 마크다운 네이티브 저장으로, 이를 통해:
- **60% 토큰 절약**
- **편집 기능 강화**
- **저장소 효율성 향상**
- **현재 UX 유지**

를 모두 달성할 수 있습니다.

특히 현재 자동포스팅되는 화면이 만족스럽다면, 백엔드에서만 수정하여 프론트엔드는 마크다운 렌더러로 동일한 결과를 출력하면 됩니다.
