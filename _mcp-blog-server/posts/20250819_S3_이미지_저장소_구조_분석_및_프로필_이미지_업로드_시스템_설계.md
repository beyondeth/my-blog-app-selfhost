## 🔍 S3 사용 현황 조회 SQL

### S3 관련 데이터 조회 SQL 쿼리

```sql
-- 1. 현재 S3를 사용하는 모든 테이블 확인
SELECT table_name, column_name 
FROM information_schema.columns 
WHERE column_name ILIKE '%s3%' 
   OR column_name ILIKE '%file%' 
   OR column_name ILIKE '%image%';

-- 2. Files 테이블의 S3 파일 분포 현황
SELECT 
    file_type,
    COUNT(*) as total_files,
    SUM(file_size) as total_size_bytes,
    ROUND(AVG(file_size), 2) as avg_size_bytes,
    MIN(created_at) as first_upload,
    MAX(created_at) as last_upload
FROM files 
GROUP BY file_type 
ORDER BY total_files DESC;

-- 3. 이미지 파일만 조회 (프로필 이미지 후보)
SELECT 
    f.id,
    f.file_key,
    f.original_name,
    f.file_size,
    f.mime_type,
    u.username,
    u.email,
    f.created_at
FROM files f
JOIN users u ON f.user_id = u.id
WHERE f.file_type = 'image' 
  AND f.mime_type IN ('image/jpeg', 'image/png', 'image/webp', 'image/gif')
ORDER BY f.created_at DESC
LIMIT 20;

-- 4. Users 테이블의 profileImage 사용 현황
SELECT 
    COUNT(*) as total_users,
    COUNT(profile_image) as users_with_profile_image,
    ROUND(COUNT(profile_image) * 100.0 / COUNT(*), 2) as percentage_with_image
FROM users;

-- 5. ProfileImage가 설정된 사용자들 조회
SELECT 
    id,
    username,
    email,
    profile_image,
    created_at
FROM users 
WHERE profile_image IS NOT NULL 
  AND profile_image != ''
ORDER BY updated_at DESC;

-- 6. S3 파일 키 패턴 분석
SELECT 
    SUBSTRING(file_key FROM 'uploads/([^/]+)') as file_type_from_path,
    COUNT(*) as count,
    ARRAY_AGG(DISTINCT mime_type) as mime_types
FROM files 
WHERE file_key LIKE 'uploads/%'
GROUP BY SUBSTRING(file_key FROM 'uploads/([^/]+)')
ORDER BY count DESC;

-- 7. 월별 이미지 업로드 통계
SELECT 
    DATE_TRUNC('month', created_at) as month,
    COUNT(*) as uploads,
    SUM(file_size) as total_bytes,
    ROUND(AVG(file_size), 2) as avg_size
FROM files 
WHERE file_type = 'image'
GROUP BY DATE_TRUNC('month', created_at)
ORDER BY month DESC
LIMIT 12;
```

## 🚀 구현 권장사항

### 방법 1: 기존 Files 테이블 활용 (권장)

**장점**: 기존 인프라 재사용, 파일 관리 일관성 유지
**단점**: 약간의 오버헤드

```typescript
// ProfileImageService 생성
@Injectable()
export class ProfileImageService {
  constructor(
    private filesService: FilesService,
    private usersService: UsersService
  ) {}

  async uploadProfileImage(userId: string, file: Express.Multer.File) {
    // 1. 프로필 이미지 전용 타입으로 S3 업로드
    const uploadResult = await this.filesService.createUploadUrl(userId, {
      fileName: file.originalname,
      mimeType: 'image/webp', // WebP 강제
      fileSize: file.size,
      fileType: 'profile' // 새 타입 추가
    });

    // 2. Users 테이블의 profileImage 필드 업데이트
    await this.usersService.update(userId, {
      profileImage: uploadResult.s3Key
    });

    return uploadResult;
  }
}
```

### 방법 2: 직접 S3 연동 (심플)

**장점**: 빠른 처리, 단순한 구조
**단점**: 파일 관리 추적 어려움

```typescript
// UserProfileService 생성
async updateProfileImage(userId: string, imageFile: File) {
  // 1. S3 키 생성
  const s3Key = `uploads/profile/${userId}/${generateUuidFileName(imageFile.name, 'image/webp', 'profile')}`;
  
  // 2. S3 직접 업로드
  const presignedUrl = await this.s3Service.generatePresignedUploadUrl(s3Key, 'image/webp', imageFile.size, 'profile');
  
  // 3. Users 테이블만 업데이트
  await this.usersService.update(userId, { profileImage: s3Key });
  
  return presignedUrl;
}
```

### 🔧 프론트엔드 구현

```typescript
// ProfileImageUploader 컴포넌트
const uploadProfileImage = async (file: File) => {
  // 1. WebP 변환
  const webpFile = await convertImageToWebP(file);
  
  // 2. 업로드 URL 요청
  const { uploadUrl, s3Key } = await fetch('/api/v1/users/profile/image/upload-url', {
    method: 'POST',
    body: JSON.stringify({
      fileName: webpFile.name,
      mimeType: 'image/webp',
      fileSize: webpFile.size
    })
  }).then(r => r.json());
  
  // 3. S3 직접 업로드
  await fetch(uploadUrl, {
    method: 'PUT',
    body: webpFile,
    headers: { 'Content-Type': 'image/webp' }
  });
  
  // 4. 업로드 완료 처리
  await fetch('/api/v1/users/profile/image/complete', {
    method: 'POST',
    body: JSON.stringify({ s3Key })
  });
};
```

### 🎯 최종 구현 순서

1. **백엔드 API 엔드포인트 추가** → `UsersController`에 프로필 이미지 업로드 라우트
2. **프로필 이미지 서비스 구현** → 기존 `FilesService` 확장 또는 새 서비스 생성  
3. **프론트엔드 업로더 컴포넌트** → WebP 변환 + S3 업로드 처리
4. **Users 프로필 페이지 연동** → 프로필 이미지 표시 및 수정 기능
5. **성능 최적화** → CDN 캐싱, 이미지 리사이징, Lazy Loading

## 📋 요약

✅ **현재 구조**: 완전한 S3 + TypeORM 기반 파일 관리 시스템 구축됨  
✅ **ProfileImage 필드**: Users 테이블에 이미 존재 (length: 500)  
✅ **S3 구조**: `uploads/{type}/{year}/{month}/{uuid}.ext` 패턴 적용  
✅ **권장방법**: 기존 Files 테이블 활용하되 'profile' 타입 추가

### 핵심 포인트

- 기존 S3 인프라 재사용으로 빠른 구현 가능
- WebP 강제 변환으로 용량 최적화  
- UUID 기반 파일명으로 충돌 방지
- Presigned URL로 서버 부하 최소화

위 SQL 쿼리들로 현재 상태를 파악하고, 제안된 아키텍처로 구현하면 효율적인 프로필 이미지 시스템을 구축할 수 있습니다.
